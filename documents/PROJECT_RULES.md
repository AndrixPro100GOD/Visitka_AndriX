# Памятка по проекту Visitka_AndriX (портфолио)

## База проекта

- Проект полностью статический: `index.html` + `index.css` + `tms-demo.css` + `ai-demo.css` + `js/site.js` + `js/tms-demo.js` + `js/ai-demo.js` + папка `images/`.
- Сборка не нужна. Сайт открывается как `file://.../index.html` и публикуется на GitHub Pages.
- Для GitHub Pages главная страница — `index.html` в корне репозитория.

## Контент и структура

- Позиционирование — разработчик программного обеспечения. C#, .NET, ASP.NET Core, EF Core и Unity — подтверждённый опыт до использования ИИ; выбор инструментов для новых задач шире этого стека. Не добавлять неподтверждённое владение новыми технологиями.
- Стек — четыре группы технологий в секции `#skills` в `index.html`.
- README — публичное описание Андрея, его опыта, подхода к разработке и сайта с действующей ссылкой на GitHub Pages. Инструкции по устройству и публикации проекта хранить в этой памятке.
- Поведение — `js/site.js`: появление блоков, счётчики, мобильное меню, прогресс чтения, активная навигация, копирование почты и интерактивное демо TMS. Композиция первого экрана, текстовая лента, иллюстрации и схема процесса реагируют на положение прокрутки в обе стороны. Геометрия пересчитывается при изменении размеров, шрифтов и раскрытии опыта; кадры запрашиваются только при изменениях. Зависимостей JavaScript нет.
- Тёмная палитра, типографика, адаптивные сетки и переходы — в `index.css`. Основные цвета заданы переменными `:root`: графитовая база, лаймовый и лавандовый акценты. Цвета участников процесса: зелёный — человек, янтарный — совместная работа, синий — агент.
- `#approach` содержит шесть этапов: задача (я), архитектура (я + агент), реализация (агент), проверка кода (агент), проверка поведения (я + агент), релиз (я + агент). Ошибки кода и поведения возвращают к реализации; ссылки возврата работают и без JavaScript. На широком экране описание закрепляется рядом со схемой; на узком располагается над ней.
- После схемы внутри `#approach` расположен `#ai-demo`: презентация «От требований до рабочей системы» на 125 секунд, десять этапов. Сохранять плавные переходы и порядок окон: рабочая среда → промежуточный интерфейс с моим ревью → проверки в рабочей среде → инфраструктура → темы проекта → ERP поверх среды разработки. Шаги 3–6 показывают самостоятельную работу разработчика в файлах; сообщения агентов служат короткими статусами, а не новыми промптами.
- ТЗ содержит .NET 10, ASP.NET Core, Blazor WebAssembly, архитектуру модулей, RBAC, интеграции, Web и мобильные клиенты, unit/integration/e2e, Docker, Kubernetes, CI/CD и наблюдаемость. Девять тем появляются постепенно; архитектура, код заказов, склад и миграции, интеграции, тесты, поставка и мобильные клиенты открываются с собственными артефактами. Мониторинг остаётся отдельной активной задачей. Разработчик записывает правила в `AGENTS.md` и `.editorconfig`, закрепляет границы модулей тестами, сам исправляет литералы и Razor-компонент, отклоняет ранний DROP COLUMN, сверяет внешний контракт и дополняет документацию. Правки `before → body` привязаны к `editAt` и восстанавливаются при перемотке. Во время сборки ERP видна отдельная карточка моего diff.
- Git показывает C#/Razor, тесты, Dockerfile, YAML и CI. Обязательная демонстрационная регрессия: разработчик дописывает негативный тест → Viewer получает 200 вместо 403 → человек останавливает merge и находит причину → сам ставит `OrderPolicies.Approve` на endpoint → полный повтор unit/integration/e2e → PASS → ревью человека. Разработчик редактирует зависимости jobs в CI/CD, проверяет Docker/probes/миграцию и дополняет runbook восстановлением и откатом. Защита production (`Required reviewers`, ветки и секреты) показывается как настройка Settings / Environments; не выдумывать поле reviewers в YAML. Production требует отдельной приёмки.
- Сцена «Под капотом»: Web (Blazor WebAssembly) и Phone → HTTPS / L7 Ingress → ASP.NET Core API в Kubernetes → PostgreSQL и Redis для SignalR backplane. Вместо числа пользователей — синтетический профиль 500 → 1 500 запросов/с. Разработчик задаёт ресурсы pod (`requests.cpu: 500m`), target CPU 60% и выдержку 3 минуты; время явно сжато. В условном устойчивом профиле CPU растёт с 26% до 78%; HPA вычисляет `ceil(2 × 78 / 60) = 3`: 2 → 3 реплики, затем CPU 52%. Показаны ровно три pod, worker-узлы, запросы, события и OpenTelemetry. Число людей не является триггером масштабирования. Это иллюстрация принципа, не бенчмарк: все значения, фрагменты кода и результаты тестов относятся к условному ERP, а не к проверкам сайта или подтверждённому коммерческому проекту.
- Сценарий презентации — `js/ai-demo.js`, оформление — `ai-demo.css`, основной интерфейс и статичный обзор ERP — в HTML. Одна шкала времени восстанавливает темы, режим чата/редактора, авторство, диффы до и после правки, ошибки, проверки и инфраструктуру при перемотке в обе стороны. Текст кода добавлять через textContent, DOM редактора и Git обновлять только при изменении состояния. Демо автоматически стартует один раз, когда видно не менее 35% сцены; пауза, повтор и десять этапов доступны с клавиатуры. Вне экрана и в скрытой вкладке часы останавливаются. При ручном переключении разделов ERP воспроизведение приостанавливается; кнопка продолжения возвращает автоматический показ.
- ERP «Пульс» и его данные — условный пример процесса, а не коммерческий продукт из портфолио. В финале работают шесть демонстрационных экранов: обзор, магазин, аналитика, заявки, команда, аккаунт. За ERP видны темы проекта; плашки напоминают о ревью, исправлениях, тестах и CI/CD. Финальный текст закрепляет роль человека в требованиях, архитектуре и качестве. Декоративная среда разработки и инфраструктура скрыты от скринридера; суть каждого этапа передаётся через живую подпись. До готовности ERP недоступна для фокуса. Без JavaScript остаются описание, статичный обзор и финальная фраза. `portfolio:motionchange` и системное уменьшение движения отключают автозапуск, курсор и переходы; первоначально показано готовое приложение. Кнопка «Далее» проходит дополнительные контрольные точки (исправление, повторный прогон, PASS, рост нагрузки и готовые реплики), чтобы существенные состояния оставались доступны без движения.
- Анимации учитывают `prefers-reduced-motion`; переключатель в подвале сохраняет выбор в `localStorage`, когда хранилище доступно. Основной контент и раскрытие опыта работают без JavaScript.
- Декоративная лента `.kinetic-track` повторяет полный цикл из `.kinetic-sequence`. Число повторов вычисляется по реальной ширине текста, ширине блока и запасу на смещение; пересчитывается при изменении размеров и шрифтов. Не заменять это фиксированным числом фраз: на ультрашироких экранах появится пустой край. Без JavaScript остаётся статичная строка, центрированная, если позволяет ширина.
- Схема терминала — условная интерактивная демонстрация, а не скриншот коммерческой TMS.
- По новой инструкции владельца TMS показывает физические операции и синхронное заполнение заявки: прибытие автомобиля → камера распознаёт контейнер → ричстакер принимает и размещает его → платное хранение → второй автомобиль → перемещение, погрузка и выезд → внешняя оплата → автоматическое закрытие. Контейнер `MOGU 133767`, 40 ft, ISO 45G0; место `Stock X1 Y1 Z1`. Старый запрет менять анимацию снят этой задачей.
- Сценарий TMS: `js/tms-demo.js`, оформление: `tms-demo.css`, SVG и карточка: `#tms-demo` в HTML. Одна шкала времени управляет геометрией техники, событиями, статусами и начислением. Состояние восстанавливается из списка событий, поэтому перемотка и повтор не удваивают оплату. Пример — 3 суток × 1 200 ₽; тариф и автомобильные номера явно обозначены как условные.

## Кэш и обновления

- При каждом релизе менять версию в query-параметрах:
  - `index.html`: `index.css?v=...`
  - `index.html`: `js/site.js?v=...`
  - `index.html`: `tms-demo.css?v=...` и `js/tms-demo.js?v=...`
  - `index.html`: `ai-demo.css?v=...` и `js/ai-demo.js?v=...`
  - при замене иллюстрации — `images/<имя>.jpg?v=...` у соответствующего `img` в `index.html`
  - при смене фона/картинок в CSS — соответствующие `?v=...`
- Формат: `v=YYYYMMDD-N` (пример: `v=20260512-1`).
- После деплоя проверить в инкогнито и с принудительным обновлением (Ctrl+F5).
